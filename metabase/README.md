# DataForge — Revenue Dashboard

Synthetic dataset → Postgres star schema → Metabase dashboard, for a fictional web-data-extraction and proxy-infrastructure company.

> All data is generated by `generate_data.py`. No real or client data is used.

[Click here to view the dashboard screenshot](https://docs.google.com/viewer?url=https://raw.githubusercontent.com/azizp128/revenue-analytics/refs/heads/main/metabase/dashboard.pdf)

## Prerequisites

- Docker + Docker Compose
- Python 3.10+
- `make` (Windows: use WSL or Git Bash)

## How to Run

```bash
make setup
```

That's it. It generates the data, boots both databases, loads the schema, and
restores the saved dashboard. Takes about 2 minutes on a cold start.

Then open: **http://localhost:3001/dashboard/2-dataforge-revenue-dashboard**

## Manual steps

If you'd rather not use `make`:

```bash
# 1 - generate the dataset
pip install numpy pandas
python generate_data.py

# 2 - start the DataForge database
docker compose up -d postgres_dataforge

# 3 - load schema and data
docker exec -i postgres_dataforge psql -U dataforge -d dataforge < sql/01_schema.sql
for f in dim_client dim_domain dim_product fact_daily_usage; do
  docker cp data/$f.csv postgres_dataforge:/tmp/$f.csv
done
docker exec -i postgres_dataforge psql -U dataforge -d dataforge < sql/02_load.sql

# 4 - recreate the Metabase app database
#     stop Metabase first, otherwise its open connections block the DROP
docker compose stop metabase
docker compose up -d postgres_metabase
docker exec postgres_metabase psql -U metabase -d postgres -c "DROP DATABASE IF EXISTS metabase;"
docker exec postgres_metabase psql -U metabase -d postgres -c "CREATE DATABASE metabase;"

# 5 - restore the saved dashboard
docker cp backup/metabase_backup_2026-08-25.dump postgres_metabase:/tmp/backup.dump
docker exec postgres_metabase pg_restore -U metabase -d metabase --clean --if-exists /tmp/backup.dump

# 6 - start Metabase (first boot takes ~60s)
docker compose up -d metabase
```

## Other commands

| Command      | What it does                                  |
| ------------ | --------------------------------------------- |
| `make help`  | List all targets                              |
| `make data`  | Regenerate the dataset only                   |
| `make reset` | Reload the data, leave Metabase untouched     |
| `make down`  | Stop all containers                           |
| `make clean` | Stop containers, drop volumes, delete `data/` |

Regenerate with different parameters:

```bash
python generate_data.py --seed 7 --days 90 --revenue 1200000
make reset
```

## Troubleshooting

**`connection refused` on step 3** — Postgres is still booting. Wait a few
seconds and retry, or use `make setup`, which waits for the health check.

**`could not open file "/tmp/dim_client.csv"`** — the `docker cp` in step 3 was
skipped. `\copy` runs client-side, so the CSVs must exist inside the container.

**Dashboard is empty after restore** — restart the container so Metabase picks up
the restored app database: `docker compose restart postgres_metabase`.
